# SQLiteDatabase.java

The single class responsible for all database communication in YallaBudget. No other class talks to SQLite directly — everything goes through here.

---

## The Database File

```java
private static final String URL = "jdbc:sqlite:yallabudget.db";
```

The database is a local file called `yallabudget.db` created in the project's working directory when the app runs for the first time.

---

## Tables

`createTables()` runs on startup and creates 4 tables if they don't already exist:

| Table | Purpose | Key Fields |
|---|---|---|
| `user` | Stores the single app user | `id`, `username`, `pin` |
| `budget_cycle` | Stores the active budget period | `id`, `total_allowance`, `start_date`, `end_date`, `remaining_balance` |
| `category` | Expense categories (Food, Health, etc.) | `id`, `name`, `description` |
| `expense` | Individual spending records | `id`, `amount`, `category_id`, `cycle_id`, `timestamp` |

### Relationships

```
budget_cycle ──< expense >── category
```

`expense` has two foreign keys:
- `category_id` → references `category(id)`
- `cycle_id` → references `budget_cycle(id)`

Foreign keys are enforced via `PRAGMA foreign_keys = ON` on every connection.

## Methods by Group

### Connection

| Method | What it does |
|---|---|
| `connect()` | Opens a JDBC connection and enables foreign key enforcement |

---

### User

The app only ever has one user, always stored with `id = 1`.

| Method | What it does |
|---|---|
| `userExists()` | Checks if a row with `id = 1` exists in the `user` table |
| `saveUser(username, pin)` | Inserts the user row with hardcoded `id = 1` |
| `loadUser()` | Fetches the user row and returns a `User` object |
| `updatePin(newPin)` | Updates the `pin` column for `id = 1` |

---

### Budget Cycle

Like the user, only one cycle is active at a time (`id = 1`).

| Method | What it does |
|---|---|
| `cycleExists()` | Checks if a cycle row exists |
| `saveCycle(cycle)` | Calls `insertCycle` or `updateCycle` depending on whether a cycle already exists |
| `insertCycle(cycle)` | Inserts a new cycle row (private) |
| `updateCycle(cycle)` | Updates the existing cycle row (private) |
| `loadCycle()` | Returns the cycle as a `BudgetCycle` object |
| `deleteCycle()` | Deletes the cycle **and all its expenses** (order matters due to the foreign key) |

> `saveCycle` is the only public write method — it decides internally whether to insert or update, so callers don't need to think about it.

---

### Categories

Categories are fixed and seeded once. They are never created or deleted by the user.

| Method | What it does |
|---|---|
| `insertCategories()` | Seeds the 6 default categories using `INSERT OR IGNORE`, so it's safe to call multiple times |
| `getCategories()` | Returns all categories as a `List<Category>` ordered by id |

The 6 default categories are: Food, Entertainment, Transportation, Shopping, Health, Education.

---

### Expenses

| Method | What it does |
|---|---|
| `saveExpense(expense)` | Inserts a new expense row (id is auto-generated by `AUTOINCREMENT`) |
| `updateExpense(expense)` | Updates amount, category, and timestamp for an existing expense |
| `deleteExpense(expense)` | Deletes a specific expense by `id` and `cycle_id` |
| `getExpensesByCycle(cycleId)` | Returns all expenses for a given cycle, with category data joined in |

`getExpensesByCycle` uses a `JOIN` so each returned `Expense` object already has its `Category` populated — the controller doesn't need to do a second query.

---

## Key Design Notes

**Every method opens and closes its own connection.** There is no shared persistent connection — each method does `connect()` inside a try-with-resources block, which guarantees the connection is closed even if an exception occurs.

**All exceptions are wrapped in `RuntimeException`.** The methods don't declare `throws SQLException`, so callers don't have to handle checked exceptions. The tradeoff is that errors will crash loudly at runtime.

**`parseTimestamp` handles two formats.** Timestamps are stored as plain text. When reading them back, the method tries `LocalDateTime.parse()` first, and falls back to `LocalDate.parse().atStartOfDay()` for older records that may have been stored as date-only strings.
